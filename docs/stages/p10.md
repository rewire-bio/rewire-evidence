## Three things the oracle decided

**The registry is older than the manifest beside it.** A registry row copies `store`, `visibility` and `source_ids` from the manifest row of its object. The registry was last written at `e70b112` on 2026-11-19. On 2026-11-20 commit `f550406` recorded R2 as the home of every object, so at the pinned commit all 1,167 manifest rows say `store: r2` and every registry row still says `github-release` or `local-cache`. `npm run layers -- check` therefore cannot pass at the pinned commit, with the TypeScript or with this. The gate takes the rows it copies from the manifest of `e70b112`, held by digest in `scripts/expected/store-layers.json`, and requires byte equality. It then measures what the pinned manifest would write instead and pins the answer: all 2,240 checked rows differ, in `store` and in nothing else. A row that differed in any other member would fail the gate.

**The bytes are not in a checkout.** `scripts/fetch_public_objects.py` fetches the release asset of every row that is public and names `github-release` as a mirror, 871 objects and 665,955,335 bytes, into a folder that CI caches on the digest of the manifest. It keeps the bytes it receives and never compresses. A public object missing from the folder fails the gate.

**A PDF layer is not a function of the bytes and the poppler version alone.** The registry names `pdftotext version 26.08.0`. No package index serves that release: Homebrew is at 26.11.0, conda-forge has 26.07.0 and 26.09.0, and apt is older. CI builds it from the source tarball, held by SHA-256, with poppler-data 0.4.12. Built on a macOS arm64 runner it writes the committed bytes for all 142 PDF rows of the public objects. Built from the same source on Linux it does not. Over the 110 public PDFs stored as they are:

| macOS 15 arm64, Apple clang | yes | 110 of 110 |
| macOS 15 arm64, Apple clang | no | 107 of 110 |

The last row was not measured with poppler-data in the prefix. Where a layer differs it is by 7 to 2,001 bytes in a layer of 110,000 to 510,000, and one differs with the same length. The cause was not determined. That fused multiply-add moves six rows on x86-64 points at floating point in the layout, and nothing here confirms it.

So the `layers` job runs on `macos-15`, and the gate refuses to run on any pdftotext whose version line is not the registry's. The Linux rows are not in the gate. They are the measurement that says where it can run.

The build is pinned by the digest of the two source tarballs. The libraries it links against are Homebrew's as the runner has them, and the runner image is `macos-15` as GitHub serves it, so neither is pinned, and the cache of the build is keyed on the tarballs alone. If the gate goes red on the PDF rows with no commit here, that is the first place to look: delete the `poppler-` cache and compare.

## Where JavaScript is the specification

`tests/fixtures/layers.json` is recorded from the TypeScript by `scripts/fixtures/record_layers_fixture.mjs` in the `fixtures` job, on cases from `layers_cases.mjs` that the stored objects have no example of: 885 cases in 27 sections, and 24 command runs on three small trees. Every one is replayed.

- **A string is UTF-16 units.** `classify` reads the first 4,096 units, not characters, and a recorded case puts the cut inside a comment of emoji where the two readings disagree. The sheet limit counts units. A cell's offsets in a grid are characters, and are recorded on tables holding characters beyond U+FFFF.
- **UTF-16 input can hold half a surrogate pair.** Node keeps it, writes U+FFFD for it in the layer, and counts it as one character. Big-endian UTF-16 of an odd length is refused by `swap16`, in Node's words, and the object is unreadable rather than unsupported.
- **`\p{L}`, `\p{Nd}` and `\s` follow Node's Unicode version.** `metrics_of` reads the recorded sets, as the locator patterns do, and a recorded case counts every code point.
- **`Number.parseInt` reads a prefix.** A span of `" 3 "` is 3, `"1.9"` is 1, and 400 nines is an infinity, which is not a count of cells.
- **A tar name ends at a NUL only if nothing after it ends a line**, because `.` stops at a line terminator.
- **An attribute named `__proto__` sets nothing** on the plain object the Office scanner keeps attributes in.
- **zlib's words are not reproduced.** A problem line that quotes zlib, for a member that will not inflate, says so in this library's words after the colon. No committed file holds such a line: `problems` reaches no registry row.

`tests/fixtures/js-semantics.json` gained `parse_int`, `buffer_text`, `until_nul`, `upper_ascii` and `inflate_raw`, recorded with built-ins only.

## Property tests

- `tidy_traced` equals a transcription of the TypeScript's loop one character at a time, and is idempotent.
- The scan a grid is built by gives the text the text layer holds, for any sequence of table markup, and every cell's offsets select its text.
- `metrics_of` equals a transcription of the TypeScript's loop over Node's recorded sets.
- A zip or a tar written by the standard library expands to its files.
- Any bytes have a layer tree or are refused in Node's words, and a layer's `identity` is true exactly when its bytes are the object's.
- A column label names its number, an escaped cell holds no control character, and UTF-8 text is its own layer.

## TypeScript behaviour noted, not changed

- `layers -- check` fails at the pinned commit, for the reason above. Measured with this port's command over all 1,167 objects: at the pinned commit it prints `data/omics/layers/registry.jsonl is not what the store produces` and `1 problems`, and at `e70b112` it prints `2595 layers reproduce`. That the TypeScript's command does the same is by reading it, not by running it. The registry needs regenerating after any manifest write that changes `store`, `visibility` or `source_ids`, or the three members should not be copied into it.
- `pdf-text-layer@1` does not reproduce across platforms at one poppler version, measured above. The data repository's `label-measure` workflow installs `poppler-utils` from apt on Ubuntu, so a PDF layer derived there is not the registered one, and `layerText` will refuse it.
- `readPinnedPdfText` gives a conversion 30 seconds, and a PDF that takes longer is recorded as having no layer. Whether a slow PDF has a layer therefore depends on the machine. The slowest stored PDF took 3.2 seconds here.
- `expandContainer` is caught by `layerOf` and by `officeLayer`, and can throw in neither place for bytes `classify` called a container. It can throw in `officeLayer` called on its own, for a file whose central directory names a workbook and whose first bytes are not `PK`.
- `encodingOf` calls bytes that open with a UTF-8 byte order mark text without checking what follows, so a binary file with that prefix gets a text layer of U+FFFD.
- A grid's `candidateHeader` and `place` and the document reader agree with the port on every recorded case. No fault was found in them.

## Running it

```sh
python scripts/fetch_public_objects.py <checkout> objects
python scripts/verify_store_layers.py <checkout> <checkout of e70b112, data/archive/objects at least> objects
```

The second needs `pdftotext version 26.08.0` on the path, built as `.github/workflows/checks.yml` builds it.
