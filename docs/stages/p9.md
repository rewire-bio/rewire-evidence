## The rules a takedown depends on

Handover section 5 names these. Each is held by recorded rows and by a property test.

- **R2 is the home, a release is a mirror.** `store` names one backend and `mirrors` the others. `mark_home` keeps the old home as a mirror unless it was `local-cache`, and `mark_mirror` adds a copy. Both return whether they wrote a row, not whether they found one.
- **A restricted row never names a public release, as home or mirror.** The rule is not applied to a removed row. A recorded removed row whose `store` is `github-release` is accepted, and the same row with a `github-release` mirror is refused for the mirror.
- **A removed row sits at `t5-no-store` and names no mirror.** `mark_removed` clears `mirrors`, so a row that had gained a release mirror can still be taken down. A property test takes down every kind of row the schema accepts, after moving its home and adding a mirror, and requires the takedown to be written, the key, byte count, origin, `first_seen_at`, `store` and `source_ids` to stay, and a later `update_row` to a public tier to be refused.
- **`reclassify` passes over a row at `t5-no-store`** before it reads anything, removed or not, and writes nothing at all when any row would move from public to restricted.
- **Nothing is recompressed.** A cached object is expanded and hashed. This stage has no code that compresses.

## Where JavaScript is the specification

- **zod.** The four schemas are held to 1,382 recorded inputs, 1,090 of them refused, with every issue zod reports in its order, and to what the schema read where it accepts. That includes the order of the refinements, which stop running after a member of the wrong type and go on after a failed pattern, and a row with no `mirrors`, which is read as having none.
- **gzip is read as Node reads it, which is not as Python's `gzip` reads it.** After a member, Node takes any byte that is not zero as the start of another member and stops at a zero byte whatever follows. Python reads on past zero bytes and refuses what follows them if it is not a member. A member, a zero byte and a second member is the first member to Node and both to Python. `archive.gunzip` is written out on `zlib.decompressobj` and held to 44 recorded files: concatenated members, zero padding, truncation, a wrong checksum, a wrong length, header flags, and the size limit `expand` passes.
- **`upsertRow` writes the row it was given, not the row the schema read.** A new row given with no `mirrors` is written with none, and the next rewrite of its shard, which writes what the schema read, gives it `"mirrors":[]`. The port does the same, and a recorded scenario shows both.
- **`upsertRow` compares lengths.** It skips the write when the merged source IDs are as many as the row had. A row holding one ID twice is rewritten by an upsert that adds nothing.
- **Line numbers differ by reader.** `readShard` drops the blank lines and then counts, so its number is among the lines left. The readers of receipts, candidates and the licence map count every line.
- **`$` and `\d`.** A pattern's `$` does not match before a final newline in JavaScript and `\d` is an ASCII digit. Every pattern here is matched whole with ASCII classes, and the recorded cases have a key, a date and a file name with a newline after them and a timestamp with an Arabic-Indic digit.
- **`trim`, `split("\n")` and lowercase** are JavaScript's, from the earlier stages.
- **`new URL`.** `weburl.host_of` gives `host` and `hostname` for the shapes the store has and for 107 of 126 recorded texts. It refuses to answer, with `UndecidedHost`, for a host that needs IDNA mapping, an IPv6 address, an opaque host that needs percent escapes and a `file:` URL. All 2,750 URLs of the pinned source records are plain `https` with an ASCII host.
- **Default `sort()` on pairs.** `moves_by_tier` and the two tallies of `counts.ts` are ordered by the text `name,count`, as `[...entries].sort()` orders them.
- **Objects list a name that is a whole number first**, which the serialisers of P1 already do.

## Where the port differs, on purpose

- **An error of the file system or of `JSON.parse` is said in this library's words**, as `StoreError`. Everything else the TypeScript throws is said in its words.
- **A file that is not UTF-8 is refused.** Node reads it with U+FFFD in place of what it cannot decode.
- **A line of `sources.jsonl` that is not an object is passed over.** The TypeScript passes over everything but a null, on which it throws.
- **`licence counts` refuses a licence string the map has no row for, by name.** The TypeScript throws a `TypeError` on it.
- **No usage text and no stack trace.** `archive` with no command, an unknown command and a bad `--date` are argparse's errors with status 2. The TypeScript prints its usage with status 0 for no command and 1 for an unknown one, and a stack trace for a bad date.
- **`host_of` refuses what it cannot decide.** See above.
- **The gate cannot be run on a checkout with an object cache.** The recording was made of a checkout with none, so `verify` and `status` are held to every object missing. `ARCHIVE_CACHE` set to an empty folder holds a working checkout to the recording, which P10 and P11 will need, since they read the cache.

## Known gaps

- **`verify` and `status` are held at the pin only with an empty cache.** With bytes present they are held by the recorded scenarios: an object that verifies, one whose row counts wrongly, one whose file is another object's, one missing, one in the wrong folder, one with zero bytes after it, one in two members, and bytes still held under a row that was taken down.
- **The pinned manifest has one kind of row.** All 1,167 are `exact-bytes` with `r2` as home, 871 with a `github-release` mirror, none removed. Derived layers, other homes and removed rows are held by the recorded corpus alone.
- **No committed row was ever refused**, so refusal is held by the recorded corpus alone.
- **`reclassify` writing is held by scenarios**, since the plan at the pin is empty.
- **The manifest writes are not serialised across processes**, here or in the TypeScript, whose queue is inside one process. Each write is one temporary file and a rename.
- **The licence resolver's report and table (`licence-resolve-2026-11-17.md` and `.tsv`) are P14**, with the resolver.
- **The gates are still not required by the repository.** `main` has no ruleset.

## What a pin bump now takes

Bumping `STORE_REF` changes what the read side is held to whenever the manifest, the receipts, the candidates, the licence map, the source records or any of the 12 TypeScript files changes, which is most bumps. The `fixtures` job fails, and its `schema-fixtures` artifact holds the new `store-archive.json` and `store-archive.jsonl.gz` to commit. The eleven `ARCHIVE_*` pins in `checks.yml` are set by hand. A changed TypeScript file fails the gate by name until the recording is committed, and a change to its behaviour shows in `tests/fixtures/archive.json`.

## Found in the TypeScript, not changed

`rewire-benchmark-data` was read and not touched.

- **The triage queue trims a licence string and the classifier does not.** `readSourceLicences` keeps the string as written and `buildTriage` trims it before the lookup. A source whose licence is ` CC BY 4.0` with a space in front is unmapped to the classifier and mapped to the queue, and one whose string has a map row with the same spaces stops the queue being built.
- **One source with no evidence takes a row private.** `readRow` takes the most restrictive tier of all the row's sources, and a source with no licence and no candidate reads as `t4-private`. If any other source of the row has evidence, the row counts as evidenced and moves to `t4-private`. A recorded row with three licensed sources and one bare one is reported as a move from public to restricted.
- **`reclassify` can move a row to `t5-no-store`.** A map row at that tier, read from a recorded licence or a candidate, moves a restricted row there with no removal recorded. The schema accepts the tier without a removal.
- **`reclassify` leaves `observed_licence` alone when the tier does not move**, so a row keeps a superseded string beside an unchanged tier.
- **`upsertRow` writes the unparsed row** and compares lengths, as above.
- **`upsertRow` ignores everything but `source_ids` on a second fetch.** A row with the same key and another byte count or origin changes nothing and reports no conflict.
- **`appendReceipt` appends to a file with no final newline on the same line**, and the next read of the file throws on it.
- **`checkManifest` reports a shard that is not JSON in V8's words**, with no file or line. This is from reading the code, not from a recording.
- **`counts.ts` throws a `TypeError`** on a licence string with no map row.
